## Security and behavior evidence

`supabase/tests/database/yorks_r38_5_team_chat.test.sql` proves:

- Direct conversations have exactly two participants and no invisible Admin;
- only Admin, Project Manager and Senior Mechanical Engineer create groups;
- only Admin creates/sends announcements;
- Project/MR membership and revocation remain authoritative;
- retries do not duplicate messages;
- backend read cursors and notification seen state synchronize devices;
- delivery/read cursors produce server-authoritative receipt marks;
- mute suppresses normal alerts while mentions remain alerting;
- private object paths cannot be read or bound without membership and verified
  intent ownership;
- size/hash mismatch and unverified attachments are rejected;
- search never leaks a conversation or message preview to a non-member.
- replies cannot cross conversations, acknowledgement/pin facts are durable,
  linked records re-check current authority, cursor pages remain bounded and an
  inactive user immediately loses read access.

`supabase/tests/database/yorks_r38_5_chat_message_lifecycle.test.sql` proves
sender-only, version-checked, idempotent edits and soft-deletes; private prior
body retention; tombstone projection; receipt counts; and direct-write/RLS
negatives. Material Request discussion remains append-only by command policy.

The complete release gate and any environment-specific limitation are recorded
in the implementing change handoff rather than fabricated in this evidence
index.
